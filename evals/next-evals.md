# TraceForge 后续评测优先级

后端测试主要验证机制正确性。2026-10-02 的 7 个合成跨模块任务重复 3 次均通过，说明当前套件已接近饱和；轨迹中仍有可避免的工具错误。下一步应增加经过人工复核的真实仓库任务、跨会话续做和更长的多阶段修改，不靠扩大合成单函数题数量来提高难度。下面的评测使用隔离 fixture 仓库、固定模型配置与预算；每个任务独立重置，并至少重复 3 次。Agent 看不到隐藏验收测试。

| 优先级 | 能力 | 场景与主要指标 |
| --- | --- | --- |
| P0 | 真实代码任务完成 | Bug 修复、明确的小功能、只读仓库问答；隐藏测试通过率、无关文件改动率、首次成功率与重复稳定性。 |
| P0 | 工具调用与审批 | 路径、参数、复合命令、网络和危险操作；有效工具调用率、应审批召回率、拒绝后副作用次数（目标 0）。 |
| P0 | 长上下文与会话分支 | 早期埋入约束，经压缩、分叉、切回后继续任务；关键事实保留率、错分支信息污染率、工具调用/结果配对错误数（目标 0）。 |
| P1 | Skill 发现与选择 | 加入相似描述的干扰 Skill 和显式调用限制；正确加载率、误加载率、读取资源路径准确率。 |
| P1 | 崩溃恢复与重放 | 在流式回答、工具执行、审批等待时强制重启；会话恢复成功率、重复副作用次数、悬空节点数。 |
| P1 | 使用成本与交互负担 | 相同任务固定质量门槛；完成时间、模型用量、工具轮次、澄清轮次与人工审批次数。 |

澄清门控还需要一组**未用于修改提示词的留出集**：同一意图的不同中文说法、真实用户对话、多个相互依赖的缺口，以及用户回答不完整的情况。除“该不该问”外，记录核心缺口是否被问到、无关问题数量、回答后的最终任务成功率。
